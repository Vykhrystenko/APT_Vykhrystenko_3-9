# MatrixLib — обробка винятків та тестування

**Версія:** 2.0.0  
**Мова програмування:** C++20  
**Тип бібліотеки:** Static Library  
**Варіант:** № 20 ("Матричні операції")

## 1. Призначення проєкту

`MatrixLib` — статична бібліотека мовою C++20 для безпечного виконання базових операцій над матрицями та векторами,
поданими у вигляді одновимірних масивів у пам'яті (row-major order).

Проєкт є модернізацією бібліотеки, розробленої під час лабораторної роботи №4. У межах цієї роботи реалізовано багаторівневу обробку винятків,
валідацію передумов, захист від цілочисельного переповнення, дотримання сильної гарантії безпеки винятків (Strong Exception Guarantee), 
демонстрацію RAII-логіки та модульне тестування за допомогою Google Test.

## 2. Основні можливості

Простір імен `MatrixLib` надає такі функції:

- `add` — додавання двох матриць (A + B).
- `multiply` — множення двох матриць (A * B).
- `transpose` — транспонування матриці (A^T).
- `multiplyVector` — множення матриці на вектор (A * v).

## 3. Передумови та інваріанти коректності

Оскільки бібліотека оперує вказівниками на масиви цілих чисел (`const int*`, `int*`), для кожної операції на вході контролюються такі умови коректності:

1. **Валідність вказівників:** усі вхідні буфери (`A`, `B`, `v`) та вихідний буфер (`result`) не дорівнюють `nullptr`.
2. **Додатність розмірностей:** кількість рядків (`rows`), стовпчиків (`cols`) та розмір вектора (`vSize`) строго більші за нуль (> 0).
3. **Математична сумісність операндів:**
   - для додавання: rows_A = rows_B та cols_A = cols_B;
   - для множення матриць: cols_A = rows_B;
   - для множення матриці на вектор: cols_A = vSize.
4. **Цілочисельна коректність:** проміжні та фінальні значення елементів не виходять за межі діапазону типу `int` .

У разі порушення будь-якої з умов обчислення перериваються генеруванням відповідного винятку.

## 4. Ієрархія винятків

Базовим класом користувацьких винятків є `MatrixException`, успадкований від `std::runtime_error` (заголовний файл `MatrixExceptions.h`).

Від нього успадковуються спеціалізовані класи:

- **`InvalidMatrixException`** — містить поле `parameter_` (метод `parameter()`), що фіксує назву некоректного аргументу;
- **`MatrixDimensionException`** — містить поле `operation_` (метод `operation()`), що фіксує назву операції, у якій виявлено несумісність розмірів.

### Повна таблиця винятків проєкту

| Тип винятку | Причина виникнення |
| `InvalidMatrixException` | Передано `nullptr` або нульову/від'ємну розмірність (<=0) |
| `MatrixDimensionException` | Несумісні розміри матриць або некоректний розмір вектора |
| `std::overflow_error` | Цілочисельне переповнення при додаванні або множенні елементів |
| `MatrixException` | Базовий тип для перехоплення будь-якої помилки бібліотеки |

## 5. Гарантії безпеки винятків

### Базова гарантія (Basic Guarantee)
Усі функції бібліотеки виконують повну перевірку передумов (вказівників та розмірностей) до початку будь-яких обчислень,
не залишаючи програму в невизначеному стані при виникненні помилки.

### Сильна гарантія (Strong Guarantee)
Функції `add` та `multiply` реалізують принцип транзакційності («усе або нічого»):
1. Усі проміжні обчислення виконуються з використанням 64-бітного типу `long long` для своєчасного виявлення переповнення та записуються у локальний буфер.
2. Копіювання результату у вихідний масив `result` відбувається лише після того, як усі елементи успішно обчислені без переповнення.
3. Якщо переповнення виникає на будь-якому елементі (навіть на останньому), викидається `std::overflow_error`, а початковий вміст масиву `result` залишається повністю незмінним.

### Гарантія відсутності винятків (`noexcept`)
Методи доступу до діагностичної інформації `InvalidMatrixException::parameter()`, `MatrixDimensionException::operation()`,
а також деструктор `~ScopeLogger()` оголошені зі специфікатором `noexcept`.

## 6. RAII та розкручування стека (`MatrixDemo`)

Для демонстрації детермінованого звільнення ресурсів під час розкручування стека (stack unwinding) використовується клас `ScopeLogger` (`include/ScopeLogger.h`),
побудований за принципом RAII: конструктор виводить повідомлення про вхід у область видимості, а `noexcept`-деструктор — про вихід із неї.

У демонстраційній програмі (`demo/main.cpp`) реалізовано три рівні вкладених викликів (`level1` -> `level2` -> `level3`):
- На рівні `level3` провокується помилка несумісності розмірностей матриць (`MatrixDimensionException`).
- Під час розкручування стека деструктори локальних об'єктів `ScopeLogger` викликаються у зворотному порядку:
  
  [ENTER] main
  [ENTER] level1
  [ENTER] level2
  [ENTER] level3
  [EXIT] level3
  [LOG] level2 caught: ...
  [EXIT] level2
  [EXIT] level1
  [MAIN] Dimension error: ...
  Program continues normally.
  [EXIT] main
  
- На проміжному рівні `level2` виняток перехоплюється за константним посиланням для логування та повторно генерується без втрати типу за допомогою `throw;`.
- У `main()` реалізовано каскад блоків `catch` від найбільш конкретного до загального (`MatrixDimensionException` -> `MatrixException` -> `std::exception`).

## 7. Демонстрація антипатернів (`AntipatternDemo`)

У застосунку `antipattern/main.cpp` продемонстровано типові помилки роботи з винятками, яких слід уникати у промисловому коді:
1. **Генерування примітивних типів (`throw 404;`, `throw std::string(...)`)** — стандартний обробник `catch (const std::exception&)` не перехоплює такі винятки,
   що змушує використовувати неінформативний `catch (...)`.
2. **Зрізання об'єктів (*Object Slicing*)** — перехоплення винятку за значенням (`catch (MatrixException ex)`) призводить до втрати полів і поведінки похідного класу.
3. **Порушення сильної гарантії безпеки** — запис результатів безпосередньо у вихідний буфер під час обчислень 
   без попередньої буферизації псує початкові дані у разі виникнення помилки посеред циклу.

## 8. Модульне тестування (`MatrixTests`)

Автоматизоване тестування реалізовано у `tests/MatrixTests.cpp` за допомогою фреймворку **Google Test** (13 тест-кейсів):

- штатне виконання `add`, `multiply`, `transpose`, `multiplyVector`;
- передача `nullptr` як вхідного або вихідного аргументу (`InvalidMatrixException`);
- передача некоректних (нульових або від'ємних) розмірностей (`InvalidMatrixException`);
- несумісні розміри матриць при додаванні та множенні (`MatrixDimensionException`);
- некоректний розмір вектора при множенні матриці на вектор (`MatrixDimensionException`);
- виявлення переповнення типу `int` при додаванні та множенні (`std::overflow_error`);
- перевірка сильної гарантії безпеки: збереження початкових значень у `result` при виникненні `std::overflow_error`;
- перевірка перехоплення власних винятків через базовий клас `MatrixException`.

Для перевірки винятків застосовуються макроси `EXPECT_THROW`, для перевірки результатів обчислень та незмінності буферів — `EXPECT_EQ`.

## 9. Залежності та збирання

Проєкт використовує:
- **C++20**;
- **CMake** (версія 3.20+);
- **vcpkg** у режимі маніфесту (`vcpkg.json`);
- **Google Test** (`GTest::gtest_main`).

### Конфігурація та збирання (через CMake Presets або командний рядок)

```bash
cmake --preset default
cmake --build --preset default
```

або вручну із зазначенням toolchain-файлу `vcpkg`:

```bash
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE="$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake"
cmake --build build --config Debug
```

### Запуск тестів

```bash
ctest --test-dir build -C Debug --output-on-failure
```

## 10. Негативний самоконтроль

Для перевірки ефективності набору модульних тестів проведено експеримент із навмисним внесенням логічної помилки 
в алгоритм множення матриць (порушення індексації під час накопичення суми добутків). Запуск `ctest` миттєво зафіксував збій 
у тесті `MatrixLibTest.MultiplyWorksCorrectly` (`EXPECT_EQ`), що підтвердило здатність тестів виявляти регресії. 
Після усунення помилки всі 13 тестів успішно пройшли перевірку.

## 11. Висновок

У результаті виконання роботи статичну бібліотеку `MatrixLib` модернізовано шляхом впровадження власної 
ієрархії винятків (`MatrixException`, `InvalidMatrixException`, `MatrixDimensionException`),суворої валідації передумов,
захисту від переповнення та забезпечення сильної гарантії безпеки під час матричних обчислень. 
Використання RAII (`ScopeLogger`) підтвердило коректне розкручування стека, а набір із 13 модульних тестів у Google Test
забезпечив верифікацію як штатних сценаріїв, так і обробки виняткових ситуацій.
